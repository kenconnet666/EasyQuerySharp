# 建表与同步（code-first）

`db.CodeFirst` 按实体的元数据建表、删表、读库结构，并把库里的表同步成实体的样子。DDL 的写法由方言决定，SQLite、MySQL、PostgreSQL、DuckDB 的语句与 Java 版逐字一致。对应 Java 的 `DatabaseCodeFirst`。

## 建表

表注释、列注释、索引、外键都写在实体上：

<!-- snippet: schema-note -->
```csharp
/// <summary>笔记：表注释、列注释、按作者与时间倒序的索引，作者列是引用 t_user 的外键。</summary>
[Table("t_note", Comment = "笔记")]
[TableIndex(nameof(AuthorId), nameof(CreatedAt), Descending = [nameof(CreatedAt)])]
public class Note
{
    [Column(PrimaryKey = true, Generated = true)]
    public long Id { get; set; }

    [Column(Comment = "标题")]
    public string Title { get; set; } = "";

    public long AuthorId { get; set; }

    public DateTime CreatedAt { get; set; }

    [Navigate(RelationType.ManyToOne, SelfProperties = [nameof(AuthorId)]), ForeignKey(Action = "ON DELETE CASCADE")]
    public User? Author { get; set; }
}
```
<!-- /snippet -->

<!-- card: schema/CreateTables sql=mysql -->
```csharp
await db.CodeFirst.CreateTablesAsync(typeof(Note));
return await db.Query<Note>().CountAsync();
```

```sql
-- MySQL
CREATE TABLE IF NOT EXISTS `t_note` ( 
`id` BIGINT(20) NOT NULL  AUTO_INCREMENT,
`title` VARCHAR(255) NULL  COMMENT '标题',
`author_id` BIGINT(20) NOT NULL ,
`created_at` DATETIME(3) NOT NULL , 
 PRIMARY KEY (`id`)
) Engine=InnoDB COMMENT='笔记';
CREATE INDEX t_note_author_id_created_at_idx ON `t_note` (`author_id` ASC,`created_at` DESC);
ALTER TABLE `t_note` ADD CONSTRAINT t_note_t_user_id_fk FOREIGN KEY (`author_id`) REFERENCES `t_user` (`id`) ON DELETE CASCADE ;
SELECT COUNT(*) FROM `t_note`;
```
<!-- /card -->

- 列类型：`[Column(DbType = "…")]` 优先，否则按 CLR 类型映射（各方言的映射见[方言](dialects.md)）。
- 可空：主键与不可空的值类型（`int`、`DateTime` 等）是 `NOT NULL`，其余 `NULL`，与 Java 版一致。
- `[TableIndex]` 不写名字时叫 `表_列_idx`（唯一索引 `_uidx`）；`Descending` 列出倒序的列。
- `[ForeignKey]` 用在对一导航上，名字是 `本表_目标表_列_fk`，`Action` 原样写在后面（如 `"ON DELETE CASCADE"`）。外键排在全部建表之后；SQLite、DuckDB 不能给已有的表加外键，写在建表语句里。
- 表已存在时建表语句跳过，但索引、外键会重复建而报错：已有的表用下面的同步。
- `db.CodeFirst.CreateTableSql(typeof(T))` 只生成语句不执行。

## 库端默认值

`[Column(DbDefault = "…")]` 是写在 `DEFAULT` 后面的 SQL 原文（对应 Java 的 `dbDefault`），不是值：字符串要自己带引号，函数按各库的写法（MySQL 的 `DATETIME(3)` 列要写 `CURRENT_TIMESTAMP(3)`）。

<!-- snippet: schema-defaults -->
```csharp
/// <summary>草稿：状态与优先级有库端默认值（DEFAULT 后面的 SQL 原样写进建表语句，字符串要自己带引号）。</summary>
[Table("t_draft")]
public class Draft
{
    [Column(PrimaryKey = true, Generated = true)]
    public long Id { get; set; }

    public string Title { get; set; } = "";

    [Column(DbDefault = "'draft'")]
    public string? Status { get; set; }

    [Column(DbDefault = "0")]
    public int? Priority { get; set; }
}
```
<!-- /snippet -->

<!-- card: schema/DbDefaults sql=mysql,oracle -->
```csharp
await db.CodeFirst.CreateTablesAsync(typeof(Draft));
await db.Insert(new Draft { Title = "周报" }).ExecuteAsync();
return await db.Query<Draft>().FirstAsync();
```

```sql
-- MySQL
CREATE TABLE IF NOT EXISTS `t_draft` ( 
`id` BIGINT(20) NOT NULL  AUTO_INCREMENT,
`title` VARCHAR(255) NULL ,
`status` VARCHAR(255) NULL  DEFAULT 'draft',
`priority` INT(11) NULL  DEFAULT 0, 
 PRIMARY KEY (`id`)
) Engine=InnoDB;
INSERT INTO `t_draft` (`title`) VALUES (?);
-- params: ['周报']
SELECT `id`,`title`,`status`,`priority` FROM `t_draft` LIMIT 1;
```

```sql
-- Oracle
CREATE TABLE IF NOT EXISTS "t_draft" ("id" NUMBER(19) GENERATED BY DEFAULT AS IDENTITY NOT NULL, "title" VARCHAR2(255) NULL, "status" VARCHAR2(255) DEFAULT 'draft' NULL, "priority" NUMBER(10) DEFAULT 0 NULL, PRIMARY KEY ("id"));
INSERT INTO "t_draft" ("title") VALUES (?);
-- params: ['周报']
SELECT "id","title","status","priority" FROM "t_draft" WHERE ROWNUM < 2;
```
<!-- /card -->

- 只影响建表与加列：插入时默认只写不为 null 的列，所以为 null 的列由库填上；要一直不写用 `[InsertIgnore]`。
- MySQL、PostgreSQL、SQLite、DuckDB 写在 `NULL` / `NOT NULL` 后面（与 Java 一致）；Oracle、达梦、SQL Server、HANA、Db2 写在前面（Oracle 系要求 `DEFAULT` 在约束前）；ClickHouse 写在后面；TDengine 没有默认值，声明了会报错。
- 不能与 `Generated` 一起用（自增列的值已经由库生成）。
- 给有数据的表加 `NOT NULL` 列时，SQLite 等库要求有默认值；SQLite 加列时默认值还不能是 `CURRENT_TIMESTAMP` 这类非常量。

## 同步

`PlanSyncAsync` 读库结构、与实体比较，得出要执行的语句与差异；`SyncTablesAsync` 得出后直接执行。同步只增不删：

- 建缺的表；`[RenamedFrom("旧名")]` 用在类上改表名、用在属性上改列名；
- 加缺的列（带注释、默认值）、补缺的索引与外键；
- 库里多出来的列、可空性不一致只写进 `Differences`，不改；不比较列类型与默认值。

<!-- snippet: schema-label -->
```csharp
/// <summary>t_tag 的下一版：表改名成 t_label，name 列改名成 title，加 color 列和唯一索引。</summary>
[Table("t_label"), RenamedFrom("t_tag")]
[TableIndex(nameof(Title), Unique = true)]
public class Label
{
    [Column(PrimaryKey = true, Generated = true)]
    public long Id { get; set; }

    [Column(DbType = "VARCHAR(30)"), RenamedFrom("name")]
    public string Title { get; set; } = "";

    [Column(Comment = "颜色")]
    public string? Color { get; set; }
}
```
<!-- /snippet -->

<!-- card: schema/SyncTables sql=mysql -->
```csharp
var sync = await db.CodeFirst.PlanSyncAsync(typeof(Label));
await sync.ExecuteAsync();
return sync.ToSql();
```

```sql
-- MySQL
SELECT TABLE_NAME AS table_name, TABLE_COMMENT AS comment FROM information_schema.TABLES WHERE TABLE_SCHEMA = DATABASE() AND TABLE_TYPE = 'BASE TABLE' ORDER BY TABLE_NAME;
SELECT TABLE_NAME AS table_name, COLUMN_NAME AS column_name, COLUMN_TYPE AS column_type, IS_NULLABLE AS is_nullable, COLUMN_DEFAULT AS column_default, COLUMN_COMMENT AS comment, EXTRA LIKE '%auto_increment%' AS is_generated, COLUMN_KEY = 'PRI' AS primary_key FROM information_schema.COLUMNS WHERE TABLE_SCHEMA = DATABASE() ORDER BY TABLE_NAME, ORDINAL_POSITION;
SELECT TABLE_NAME AS table_name, INDEX_NAME AS index_name, NON_UNIQUE = 0 AS is_unique, COLUMN_NAME AS column_name FROM information_schema.STATISTICS WHERE TABLE_SCHEMA = DATABASE() AND INDEX_NAME <> 'PRIMARY' ORDER BY TABLE_NAME, INDEX_NAME, SEQ_IN_INDEX;
SELECT TABLE_NAME AS table_name, CONSTRAINT_NAME AS constraint_name, COLUMN_NAME AS column_name, REFERENCED_TABLE_NAME AS referenced_table, REFERENCED_COLUMN_NAME AS referenced_column FROM information_schema.KEY_COLUMN_USAGE WHERE TABLE_SCHEMA = DATABASE() AND REFERENCED_TABLE_NAME IS NOT NULL ORDER BY TABLE_NAME, CONSTRAINT_NAME, ORDINAL_POSITION;
ALTER TABLE `t_tag` RENAME TO `t_label`;
ALTER TABLE `t_label` CHANGE `name` `title` VARCHAR(30) NULL;
ALTER TABLE `t_label` ADD `color` VARCHAR(255) NULL COMMENT '颜色';
CREATE UNIQUE INDEX t_label_title_uidx ON `t_label` (`title` ASC);
```
<!-- /card -->

`PlanSync(types, tables)` 与保存下来的结构（`DbTableInfo`）比较，不连库，适合在发布流程里先审阅语句。

## 读库结构

<!-- card: schema/ReadTables sql=pgsql -->
```csharp
var tag = (await db.CodeFirst.ReadTablesAsync()).Single(t => t.Name == "t_tag");
return new { tag.Name, Columns = tag.Columns.Select(c => $"{c.Name} {c.Type}{(c.Nullable ? "" : " NOT NULL")}").ToList(), tag.PrimaryKey };
```

```sql
-- PostgreSQL
SELECT t.relname AS table_name, obj_description(t.oid, 'pg_class') AS comment FROM (SELECT c.oid, c.relname FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = current_schema() AND c.relkind IN ('r', 'p')) t ORDER BY t.relname;
SELECT t.relname AS table_name, a.attname AS column_name, format_type(a.atttypid, a.atttypmod) AS column_type, NOT a.attnotnull AS is_nullable, pg_get_expr(d.adbin, d.adrelid) AS column_default, col_description(t.oid, a.attnum) AS comment, (a.attidentity <> '' OR coalesce(pg_get_expr(d.adbin, d.adrelid), '') LIKE 'nextval(%') AS is_generated, EXISTS (SELECT 1 FROM pg_index i WHERE i.indrelid = t.oid AND i.indisprimary AND a.attnum = ANY (i.indkey)) AS primary_key FROM (SELECT c.oid, c.relname FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = current_schema() AND c.relkind IN ('r', 'p')) t JOIN pg_attribute a ON a.attrelid = t.oid LEFT JOIN pg_attrdef d ON d.adrelid = a.attrelid AND d.adnum = a.attnum WHERE a.attnum > 0 AND NOT a.attisdropped ORDER BY t.relname, a.attnum;
SELECT t.relname AS table_name, ic.relname AS index_name, i.indisunique AS is_unique, coalesce(a.attname, pg_get_indexdef(i.indexrelid, k.ord::int, true)) AS column_name FROM (SELECT c.oid, c.relname FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = current_schema() AND c.relkind IN ('r', 'p')) t JOIN pg_index i ON i.indrelid = t.oid AND NOT i.indisprimary JOIN pg_class ic ON ic.oid = i.indexrelid CROSS JOIN LATERAL unnest(i.indkey) WITH ORDINALITY k(attnum, ord) LEFT JOIN pg_attribute a ON a.attrelid = t.oid AND a.attnum = k.attnum ORDER BY t.relname, ic.relname, k.ord;
SELECT t.relname AS table_name, c.conname AS constraint_name, a.attname AS column_name, r.relname AS referenced_table, ra.attname AS referenced_column FROM (SELECT c.oid, c.relname FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = current_schema() AND c.relkind IN ('r', 'p')) t JOIN pg_constraint c ON c.conrelid = t.oid AND c.contype = 'f' JOIN pg_class r ON r.oid = c.confrelid CROSS JOIN generate_series(1, array_length(c.conkey, 1)) k(ord) JOIN pg_attribute a ON a.attrelid = t.oid AND a.attnum = c.conkey[k.ord] JOIN pg_attribute ra ON ra.attrelid = r.oid AND ra.attnum = c.confkey[k.ord] ORDER BY t.relname, c.conname, k.ord;
```
<!-- /card -->

`ReadTablesAsync()` 读当前 schema 的表、列（类型、可空、默认值、注释、自增）、主键、索引、外键；`TableExistsAsync(typeof(T))` 判断表是否存在。TDengine 不支持读结构，所以也不能同步。

## 分库分表

分片的实体按规则的每个节点在节点所在的数据源上建表、删表、同步，见[分库分表](sharding.md#code-first)。按时间分表时新一期的表不会自动建，定期调用 `SyncTablesAsync` 补上。

## 限制

- 只增不删：不删列、不改列类型、可空性与默认值，这些改动要自己写迁移语句。
- 没有迁移历史与回滚，也不生成迁移文件；需要版本化的迁移用专门的工具（DbUp、FluentMigrator 等），code-first 用来建测试库和开发库。
- MySQL 改列名用 `CHANGE`（整列重定义，会带上类型、可空、自增、默认值与注释，5.7 也能用）。

## 对应 Java

| Java | C# |
|---|---|
| `getDatabaseCodeFirst()` | `db.CodeFirst` |
| `createTableCommand(..)` / `dropTableIfExistsCommand(..)` 再 `executeWithTransaction(..)` | `CreateTablesAsync(..)` / `DropTablesIfExistsAsync(..)` |
| `syncTableCommand(..)` | `PlanSyncAsync(..)`（得出 `CodeFirstCommand`，`ToSql()` / `ExecuteAsync()`）/ `SyncTablesAsync(..)` |
| `tableExists(..)` | `TableExistsAsync(..)` |
| `@Table(comment, oldName)` | `[Table(Comment = …)]`、`[RenamedFrom("…")]` |
| `@Column(dbType, comment, dbDefault, oldName)` | `[Column(DbType = …, Comment = …, DbDefault = …)]`、`[RenamedFrom("…")]` |
| `@Column(nullable, length, scale)` | 可空由 CLR 类型决定；长度、精度写进 `DbType` |
| `@TableIndex` / `@TableIndexes` | `[TableIndex(..)]`（可以写多个） |
| `@ForeignKey` | 对一导航上的 `[ForeignKey(Action = …)]` |
